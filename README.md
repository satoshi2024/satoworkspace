現在適用している最終チューニング版（最新の修正内容）を以下にまとめました。

【バックエンド側のチューニング（最新版）】
対象：PDF/TIFF変換処理（ImageService.java 等）
Ghostscript（PDF→TIFF変換）のコマンドを以下のように最適化しました。
・フォーマット変更：白黒2値（tiffg4）から、縮小時に境界が滑らかになるグレースケール（tiffgray）へ変更。
・解像度最適化：フロントエンドでの極端な縮小を防ぐため、解像度を -r300 に設定。
・最高品質のアンチエイリアス強制適用：文字と図形に対し、Ghostscriptの最高レベルの平滑化オプション（-dTextAlphaBits=4, -dGraphicsAlphaBits=4）を追加。

【フロントエンド側のチューニング（最新版）】
対象：Canvas描画処理（ImageViewer.js 等）
・Canvas描画時の平滑化：画像描画時（drawImageメソッド内）に、ブラウザの最高品質アンチエイリアス処理（ctx.imageSmoothingEnabled = true, ctx.imageSmoothingQuality = 'high'）を強制的に適用するよう修正。

※注記：当初検証した「段階的縮小アルゴリズム（Step-down scaling）」や「Imageオブジェクトへの変換バイパス」についても実装・テストしましたが、TIFFを展開する中間ライブラリ（Tiff.js）の内部仕様（メモリ制限による強制的なダウンサンプリング）に起因するピクセル欠損がボトルネックとなっており、上記以上の改善が見込めなかったため、パフォーマンスと安定性を考慮し現在のシンプルな平滑化処理（上記2点）に着地させております。

【現状の結論】
現在、既存のアーキテクチャ（Ghostscriptによる生成 ＋ HTML5 Canvas/Tiff.jsによる描画）において適用できる、最も画質が高くなるパラメータ設定を行っています。
しかしながら、これでも等倍・縮小表示時の文字のぼやけを旧システム（ネイティブ描画コンポーネント）と完全に同等レベルにするのは、ブラウザ側の描画アルゴリズムの限界により困難な状態です。
